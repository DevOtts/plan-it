# Decisions: created history and plan gate (do-it 1.0.1)

- [DEFAULTED] Creation entry shape: `from: 'not-started', to: 'not-started', by: 'plan-it', note: 'created'`. Recommendation: keep. `validate` chains `from` against a default previous state of `not-started` and requires string `from`, so `null` is rejected and no validate rule was weakened.
- [DEFAULTED] `init --merge` records `created` only for tasks it adds (including tasks of a new wave); existing tasks get no second entry. Recommendation: keep.
- [DEFAULTED] Gate lives in `status-from-plan.mjs` (`gateCheck`, `--gate`); it does not require `created` entries, so boards made before 1.0.1 still pass. Recommendation: keep; add that check only if old boards are retired.
- [DEFAULTED] Existing build-it tests that counted history entries now exclude `created` entries; one hand-built migration fixture clears history first because a `migration` entry may not follow writer entries. Recommendation: keep.
- [DEFAULTED] plan-it tests locate the writer through DOIT_STATUS_WRITE; they need the build-it `feat/created-history` writer until it merges.

# Decisions: status-from-plan waves, case mapping and generated-board handoff (H-12, H-13, H-14)

- [DEFAULTED] Wave spellings read: `**Wave:** W0`, `**Wave: W0**`, `Wave: W0`, `- Wave: W0`, `| Wave: W0 |` inline, `· **Wave:** W0` mid-line, a `| Wave | W0 |` row, and line-leading `Wave 0`. A bare "wave" in prose (needs `:`/`=`/cell) does not count; the old `wave 3` mid-prose form is dropped for that reason. Search window: the epic header, up to the first checklist item or Test Contract heading, 40 lines (was 12; the real package had the wave on a branch line, mid-line). Recommendation: keep.
- [DEFAULTED] No silent default: some epics with a wave and some without refuses (exit 1, lists file:line per epic); no wave anywhere gives one `W1` with a one-line warning on stderr, silenced by `--default-wave` (boolean flag). Recommendation: keep.
- [DEFAULTED] Case mapping order: Task column, then id (`T-<EID>-NN` -> task `<EID>-NN`, numeric compare so `T-X-1` = `X-01`), then the epic. Epic-level cases are attached to every task of the epic. A task still without a case (more tasks than cases) carries the epic's whole contract (reported as "inherited"). A Task column naming a non-existent task is "unmapped" (warning with file:line) and is not guessed onto anything else. Recommendation: keep.
- [DEFAULTED] A command is only lent to the task it was written for: a Check command on an epic-level or inherited case shows the case as covered but is demoted to `none` ("epic-level case, not mapped to this task") so recheck never runs one command N times for tasks it was not written for. This keeps the existing R-1 test "a checklist task no case names stays unchecked". Recommendation: keep; revisit only if authors want epic-level commands run once per epic.
- [DEFAULTED] `--gate` gained a fourth check, "every task has a Test Contract case" (task with no case while its epic has cases fails). The reason string for a missing Check column changed from "no check column" to "no Check column in the Test Contract" (one existing assertion updated). Recommendation: keep.
- [DEFAULTED] Handoff: a `.md` whose first line is the generated marker is removed from the hand-written-board lint and replaced by `status-from-plan --gate` on the package holding status.json (found in the handoff dir or its parent): exists, writer validate, task count equals the epics' checklists, a case per task. If the shared writer is not installed it degrades to a structural check and says so. A marker not on line 1 does not exempt a file. Recommendation: keep.
- [DEFAULTED] Templates: the epic block in templates.md now uses `- [ ]` items (the generator only reads that form; the old `[ ] task` lines were never parsed) plus `**Wave:**`, `Task` and `Check` columns. Recommendation: keep.
- [NOTED] Not done: no version bump, no CHANGELOG entry (the release is run by the team lead).
- [DEFAULTED] Table rows are split by one splitter (`splitCells` in status-from-plan.mjs, `splitTableRow` in gate-check.mjs, same logic): `\|` is a literal pipe, a `|` inside a backtick span (any backtick run length) does not split. A Test Contract row whose cell count differs from its header is not read at all (no Task, no Check), reported as a warning with file:line, still counted as an epic-level case, and fails `--gate` ("Test Contract rows match their header"); the exit code of plain generation is unchanged. gate-check's only reader of Test Contract columns (`lintVerifyColumn`) uses the same splitter. Recommendation: keep.
