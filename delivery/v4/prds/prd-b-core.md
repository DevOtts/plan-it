## 1 · Summary

SQ-B owns the deterministic half of plan-it: the statechart the skill walks, the `gate-check` verbs that turn guards into exit codes, the PreToolUse guard that refuses deliverable writes against an unfrozen contract, and the harness that proves all of it. v4 asks this lane for four things, all additive over 3.0.1: (1) a 25-state machine that carries the autonomous-draft path (triage → anamnesis → … → render → plan review → freeze) beside the unchanged guided path; (2) a `state` verb that enforces the new payloads (triage memo, applied defaults, plan-review artifact, draft-cannot-hand-off, mode consistency) and a `freeze --draft`; (3) named runs — one state file per run, every verb resolving its package directory from `run.deliveryRoot`, a guard that resolves the run by path prefix in BOTH shipped copies, and `archive`/`runs` verbs; (4) three new lints embedded in `handoff` (`mirror` stamp freshness, `glossary` first-use coverage, disposition counting in `reconcile`) plus the harness amendments (AMD-4 gate count, AMD-5 eleven mirror pairs) and the v4 case discovery that lets `run-contract` execute this very CONTRACT's `## Cases` table. Nothing in 3.0.1 is renamed, removed or re-meant; `machine-diff` against a byte-pinned 3.0.1 machine and against the v2 pin is the release gate.

## 2 · Problem & goals

**What is broken today (measured, Stream B).** The guard resolves a named run only through a `docs/implementation/<name>/` path and, until W0, only in the root copy — a write under `delivery/v4/prds/` on a two-run project is denied by the wrong run (F-B8, F-B1). Six behaviour-bearing sites in `gate-check.mjs` hardcode `.plan-it/state.json`, `testconv` WRITES the generic file, and `reconcile`/`contract`/`adversary`/`freeze --dir` hardcode `delivery/v3/` — a package at `delivery/v4/` gets false greens (F-B9, F-B12, F-B14). The machine has one linear path and three chat gates; nothing distinguishes a draft contract from a final one, and nothing stops a draft from reaching `handoff` (F-B10, F-B13). Two harness assertions (`T-E1-05` exactly-three-gates, `T-E1-03` closed check set) break on any machine with new gates (F-B6). There is no vocabulary check for glossary IDs, no disposition grammar, no md↔html freshness check, and the ENV-FACTS ABSENT-tool cross-check blacklists every token of a failed probe's argv, so one failed `node …` probe marks every `node …` case unrunnable (LG-7).

## 3 · Users & jobs

1. **The skill resuming a run.** After a crash or a fresh session it runs `state --dir . --run <slug>` and needs: the exact position, only the events its mode can fire next, and a REJECT with a named fix when the state file claims something the disk cannot back (missing memo, missing PLAN-REVIEW.md, draft at handoff). It must never be told to fire a guided event on an autonomous run.
2. **The guard deciding a write.** In under a few milliseconds, with no network and no model, given only the hook JSON: which run governs this path? If none, allow. If the governing run is frozen (any non-empty `contract.version`, draft included — R1), allow. Otherwise deny and name the RESOLVED state file so the human fixes the right run. Any error → allow (fail-open, always).
3. **The orchestrator archiving.** At the end of a program: `runs` to see the portfolio with computed counts, `archive <slug>` to move a finished run to `.plan-it/done/` and refuse a live one — no `--force`, because a non-terminal run is finished or triaged, never swept away.
4. **The harness.** `node tests/run-contract.mjs` must discover the v4 CONTRACT's `## Cases` table the same computed way it discovers v3's, run each row with the right polarity (violating fixture ⇒ non-zero; harness script ⇒ zero), and report PENDING rather than false-pass a row whose mechanism is not on disk. Every new check must name its case ID in its failure message so `mechanismGap` can see it (F-B17).

## 4 · Solution design (D-B1 … D-B15)

**D-B1 — The v4 machine is the Stream B §4.1 table, verbatim, with camelCase state ids.** `machine.json` gains eight states (`triage`, `closedWithoutPlan` [final], `anamnesis` [gate G0, human], `scopeBrief`, `defaultsApplied`, `render`, `planReview` [gate G4, human, `meta.records: ["G2","G3"]`], `freeze`), three guards (`triageRecorded`, `defaultsRecorded`, `planReviewed`, all `check: "state"` so `T-E1-03`'s closed set survives), new events on baseline states (`SPECS_DRAFTED_AUTONOMOUS` on `specAuthoring`, `COHERENT_AUTONOMOUS` on `coherencePass`), three retargets through NEW states (`intake.INTAKE_CAPTURED → triage`, `dodLock.DOD_LOCKED → scopeBrief`, `adversaryGate.ADVERSARY_CLEAN → render`), `context.mode`/`context.deliveryRoot`/`context.topology`, `meta.stateFile: ".plan-it/<slug>.state.json"` + `meta.stateFileFallback`, `version: "4.0.0"`. Mode-specific transitions carry `meta.mode` on the transition object (`"autonomous-draft"` or `"guided"`); untagged = both. The terminal non-plan state has id `closedWithoutPlan` and `meta.title: "CLOSED_WITHOUT_PLAN"`, so the `state` verb's unchanged printout (`gate-check.mjs:1062`) reads `state: closedWithoutPlan — CLOSED_WITHOUT_PLAN` / `next events: (final state)` (satisfies C-E6-02; naming divergence flagged in §9 item 1). ## 7 · Risks & open questions

- **Stamp format drift.** `mirror` consumes the CONTRACT §4.3 stamp verbatim (relpaths relative to the twin's directory). If SQ-A resolves relpaths against the repo root instead, both lanes are wrong against the CONTRACT, not against each other — the fix is an amendment, never a local accommodation. The mirror fixtures are hand-stamped per §4.3 so V4B4 is testable before the renderer exists.
- **The two lanes share no files but share `handoff`'s output.** SQ-A renders; SQ-B checks freshness. A twin rendered with a `--brand` override stamps `repo:<relpath>`; `mirror` must find that file relative to the twin. Covered by `T-V4B4-05`.

- **Glossary token grammar is heuristic.** An ID-shaped token that is not an ID (e.g. `HTTP2`) is stoplisted; a new false positive is fixed by extending the stoplist, never by loosening the match. Family patterns make per-run IDs cheap to declare.
- **Polarity in `run-contract` is inferred from the `run:` shape.** A gate-check row that is meant to PASS on a positive fixture would be misread as negative. None of this CONTRACT's gate-check rows is positive (every `run:` names a violating fixture); positive checks live in `tests/v4/core/*.mjs` scripts, which are read as positive. If the orchestrator ever adds a positive gate-check row, the row must carry `(positive)` in its description and the parser honours it (D-B13).
- **W0/W1 ordering of the byte-pin.** If the orchestrator's W0 pin and V4B1's verification disagree on the hash, V4B1 fails closed and reports — it never overwrites the pin.
